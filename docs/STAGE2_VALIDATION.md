Android 테스트는 기존 상태 전이/취소/복구, 서버 성공/실패/재시도/중복 요청 방지,
임시 토큰의 UI 노출 방지, 잘못된 응답 및 만료 검증을 포함합니다.

서버 단위 테스트는 공식 client_secrets 요청/응답 형식, 장기 키 요청 헤더 사용,
오류 응답의 민감한 본문 제거, 로그인/App Check/다른 앱/재사용 토큰 거부,
시간 창과 발급 한도를 검증합니다. OpenAI 응답은 주입한 가짜 HTTP 응답입니다.

에뮬레이터에서는 다음을 실제 HTTP 및 Firestore 트랜잭션 경로로 확인했습니다.

- 같은 UID의 동시 요청 5개 중 1개만 예약, 나머지 4개는 요청 제한으로 거부.
- 전체 한도를 채운 상태에서는 다른 UID도 발급 예약 거부.
- 클라이언트의 카운터 읽기/변경은 Firestore 규칙에서 403으로 차단.
- 인증/App Check 없는 callable HTTP 요청은 401로 거부.
- Firebase Auth 에뮬레이터에서 발급한 ID 토큰만 있고 App Check가 없는 요청도 401로 거부.

실제 Firebase 프로젝트 대신 `demo-englishtalk` 에뮬레이터를 사용했습니다.
운영 API 키를 사용하지 않았으며 테스트용 가짜 값만 로컬 제외 파일에 넣었습니다.
개발 PC는 Node 24.15.0이므로 로컬 에뮬레이터는 Node 24로 실행되었습니다.
서버 배포 런타임은 Node 22로 지정했습니다. 배포 런타임 호환성을 추가 확인하기 위해
Node 22.23.3에서 서버 단위 테스트 5개를 재실행했고 모두 통과했습니다.

## 실제 프로젝트 연결 결과

초기 로컬 검증 이후 사용자가 Android 앱 등록, 익명 로그인, Firestore 생성,
App Check 디버그 토큰 등록, Blaze 전환 및 Secret Manager 키 등록을 완료했습니다.
설정 파일의 프로젝트/패키지 일치를 확인하고 Firebase 설정을 포함한 Android 빌드도 성공했습니다.
함수 배포 후 App Check 검증 권한을 설정했으며 OpenAI 401 응답을 진단했습니다.
사용자가 API 키를 다시 등록하고 재배포한 뒤 앱에서 **인증 성공**을 확인했다고 보고했습니다.
실제 기기 성공 결과는 사용자 확인이며, 서버 로그에서는 이전 실패의 IAM 권한 오류 및 OpenAI 401을 확인했습니다.
진단용 함수는 키나 오류 본문 없이 OpenAI HTTP 상태만 기록합니다.

| 완료 조건 | 상태 |
|---|---|
| Android → Firebase 호출 | 실제 프로젝트 요청 확인 및 앱 인증 성공 사용자 확인 |
| Firebase → OpenAI 인증 | API 키 재등록/재배포 후 앱 인증 성공 사용자 확인 |
| 장기 키가 앱에 노출되지 않음 | 앱은 장기 키를 받지 않으며 서버 Secret 바인딩만 사용. 실제 키를 코드/저장소에 저장하지 않음 |
| 인증 성공/실패 구분 표시 | 자동 테스트 통과 및 실제 앱에서 실패/성공 표시 사용자 확인 |

재현 절차는 [Firebase 설정 절차](FIREBASE_SETUP.md)를 참고합니다.
Secret 입력은 표시되지 않으므로 전체 키를 한 번만 붙여넣어야 합니다.
WebRTC 음성 연결은 이번 단계에 포함하지 않았습니다.
